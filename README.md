> **核心原则：AI只负责内容，程序负责工程**
> **6 位跨领域专家围绕一本书展开 7 轮深度交锋。不蒸馏知识框架，只榨干认知增量。**

## 系统架构

```
AI生成JSON内容
    ↓
Schema验证 (Pydantic)
    ↓
渲染引擎 (render.py)
    ↓
HTML模板渲染
    ↓
自动验证 (validator.py)
    ↓
最终HTML
```

## 工作流程

### Step 1: AI生成JSON内容

AI **只负责生成JSON**，不负责HTML：

```json
{
  "title": "书名",
  "dashboard": {
    "total_experts": 6,
    "total_rounds": 7,
    "experts": ["专家1", "专家2", ...]
  },
  "rounds": [
    {
      "round_number": 1,
      "topic": "讨论主题",
      "speakers": [
        {
          "name": "专家名",
          "role": "角色",
          "content": "发言内容"
        }
      ],
      "clashes": [
        {
          "type": "情节反驳",
          "expert": "专家名",
          "content": "碰撞内容"
        }
      ],
      "insight": {
        "statement": "洞见句",
        "explanation": "洞见说明"
      }
    }
  ]
}
```

### Step 2: 渲染HTML

```powershell
cd engine
python render.py "..\content\书名.json" "..\output\书名.html" "..\templates"
```

### Step 3: 验证HTML

```powershell
python validator.py "..\output\书名.html"
```

**必须PASS**，否则不交付。

## 核心组件

### Schema定义 (schema.py)

使用Pydantic定义内容结构：

- `RoundtablePPT` - 完整PPT结构
- `Round` - 讨论轮次
- `Speaker` - 发言者
- `Clash` - 碰撞交锋
- `Insight` - 核心洞见

### 渲染引擎 (render.py)

负责JSON→HTML转换：

- 读取JSON内容
- 验证Schema
- 渲染slides
- 输出HTML

### 验证器 (validator.py)

自动检查生成的HTML：

- HTML结构：slide数量、active状态
- JS完整性：go()函数、事件监听
- CSS完整性：display、字体、配色
- 组件完整性：发言块、碰撞块、洞见卡
- 动画属性：data-anim

## 设计系统

### 字体

- **元数据**: IBM Plex Mono
- **标题**: Noto Serif SC
- **正文**: Noto Sans SC

### 配色

- **背景**: #0a0a0b
- **文字**: #f1efea
- **强调色**: #c23b22（红）
- **金色**: #d4a843

### 组件

- `.sp` - 发言块（卡片式设计，左侧彩色边条）
- `.cb` - 碰撞块（虚线边框，颜色区分类型）
- `.insight-c` - 洞见卡（渐变背景，顶部金色装饰线）
- `.metric` - 指标卡（简洁卡片，大号数字）

### 动画

- 入场动画：`[data-anim]` 属性
- 进度条：顶部渐变进度指示
- 平滑过渡：所有交互都有缓动效果

## 质量红线

### 内容深度

- 发言字数 < 350字 → 无效发言
- 无书中情节引用 → 无效发言
- 无因果推理链 → 无效洞见
- 无专家间直接反驳 → 无效碰撞

### 排版规范

- 每页最多2-3人发言
- 碰撞块颜色标记
- 标题页大留白

### 框架结构

- 三层架构：洞见全景30% + 深度讨论50% + 认知演化20%
- 讨论仪表盘
- 张力图谱
