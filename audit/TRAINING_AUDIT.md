## 三、发现的问题

### P0 — 防御率维度失效

**问题**：所有文件防御率 = 0%，因为 V8 JSON 的 `clash_rounds` 中 `counter_attack` 字段全部为 `None`。

**根因**：`render_v8.py` 生成的 JSON 结构中，碰撞轮次只包含攻击，不包含反击。`counter_attack` 字段存在于 schema 但从未被填充。

**影响**：评分器的"防御成功率"维度（权重 20%）完全失效，所有讨论的满分上限只有 80 分。

**修复方案**：
- A. 在 SKILL.md 中要求讨论生成时填充 `counter_attack` 字段（改流程）
- B. 将防御率的判定改为"被攻击后有回应发言"（改评分逻辑）
- C. 暂时将防御率权重分配给其他维度（改权重）

**建议**：选 B — 从 `stances` 中找被攻击方在下一轮的发言作为"隐式反击"。

### P1 — 攻击效率阈值过严

**问题**：多个文件攻击效率 = 0%。要求"有证据 + 有逻辑链"同时满足才判定有效，但 V8 JSON 中的攻击内容多为观点性攻击，缺少具体数字引用。

**根因**：评分标准假设攻击应该包含"数字/案例/引用"，但实际讨论中攻击更多是"逻辑矛盾指出"和"观点质疑"。

**修复方案**：放宽判定标准 — 有逻辑关联词（但是/然而/问题是）+ 长度 > 100 字即判定有效。

### P1 — 认知贡献和案例质量固定值

**问题**：所有文件认知贡献 = 33%、案例质量 = 33%，因为 V8 JSON 固定 3 轮，每轮只检查 `cognitive_upgrade` 和 `reality_cases` 是否存在。

**根因**：V8 结构中只有 1 个轮次有 `cognitive_upgrade`，1 个轮次有 `reality_cases`，所以 1/3 = 33%。

**修复方案**：改为检查内容质量而非存在性 — 有 `cognitive_upgrade.new_thinking` 且长度 > 50 字才计分。

### P2 — 专家库为空

**问题**：`expert-library/experts/` 下 5 个分类目录全部为空。

**影响**：互搏模式无法运行，提取器无法关联专家档案。

**修复方案**：从已有讨论中提取专家信息，创建初始专家档案。

### P2 — 训练日志目录缺失

**问题**：`memory/{书名}_training_log.json` 约定的日志格式与 `trainer.py` 实际输出格式不一致。

**修复方案**：统一日志格式，trainer 保存时自动使用约定路径。

## 四、策略设计评估

### 4.1 "替换而非追加"原则 — 评估：优秀

专家 .md 保持恒定大小，密度递增。这避免了 .md 无限膨胀导致的：
- 上下文窗口溢出
- 专家风格稀释
- 训练效果递减

**实现验证**：`upgrader.py` 中发言 5 条恒定、金句 6 条恒定、案例 4 个恒定。替换逻辑正确。

### 4.2 "提取策略而非内容"原则 — 评估：良好

5 类策略数据（攻击/防御/证据/交互/风格）覆盖了专家能力的核心维度。

**不足**：提取器生成的是"提示词"而非"结构化数据"。实际提取需要 AI 执行，结果质量取决于 AI 的分析能力。

### 4.3 "三种训练模式"设计 — 评估：良好

| 模式 | 可行性 | 依赖 |
|------|--------|------|
| 人给话题 | 高 | 讨论 JSON 已有 |
| 互搏模式 | 中 | 需要至少 2 位专家 + 主 SKILL 生成讨论 |
| 回放训练 | 中 | 需要历史训练日志 |

**不足**：互搏模式的"自动讨论生成"尚未实现。话题生成器只生成话题文本，不生成讨论 JSON。需要手动调用主 SKILL.md。

### 4.4 7 维评分体系 — 评估：需改进

| 维度 | 状态 | 问题 |
|------|------|------|
| 攻击效率 | 需调优 | 阈值过严，0% 率过高 |
| 防御成功率 | 失效 | V8 JSON 无 counter_attack 数据 |
| 证据命中率 | OK | 正常工作 |
| 风格辨识度 | OK | 正常工作 |
| 认知贡献 | 需调优 | 固定 33%，检查逻辑太简单 |
| 案例质量 | 需调优 | 固定 33%，检查逻辑太简单 |
| 结构完整性 | OK | 正常工作 |
