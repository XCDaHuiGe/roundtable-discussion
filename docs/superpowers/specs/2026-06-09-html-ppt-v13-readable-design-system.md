# HTML-PPT V13 阅读型设计系统规格

## 目标

V13 解决的问题不是翻页稳定性，而是输出质量。

V12 已经建立稳定主链路：页面计划、容量拆页、单一渲染、最终验收。  
V13 在 V12 之上增加 **阅读型 PPT 设计系统**，让生成结果从“能翻页、能显示”升级为“别人不听讲也能看懂、愿意读、信息量足够、视觉上高级”。

核心目标：

- 输出是 **给人看的 PPT**，不是给人讲的 PPT。
- 每页是一张可独立阅读的高级知识卡片。
- 设计、排版、生图、配图逻辑沉淀为规则，不依赖某个 GPT 临场发挥。
- 没有 GPT 时，仍然能输出稳定、清楚、高信息密度、可读的 HTML-PPT。
- 有 GPT 时，用 GPT 提升标题、洞见表达、页面 brief 和视觉判断，但最终仍由规则和验收器裁判。

## 产品定位

V13 的产物应更接近：

- 咨询报告 slide document
- 高级研究简报
- 出版级信息图页
- 知识型长图的分页版本
- 可读的圆桌会议内参

V13 不追求：

- 演讲背景页
- 只放一个大标题的大屏页
- 概念海报
- 纯视觉冲击图
- 低信息密度的 keynote 页面

## 模式分层

### 1. GPT 增强模式

当 GPT 可用时，GPT 负责：

- 把内容转成页面设计 brief。
- 改写页面标题和一句话结论。
- 判断页面类型。
- 提炼论点、证据、冲突、读者带走什么。
- 为生图/配图生成中文 art direction。
- 给复杂关系选择合适的信息图结构。

GPT 不负责：

- 直接输出最终任意 HTML。
- 绕过容量规则。
- 绕过页面合同。
- 绕过验收器。

### 2. 无 GPT 稳定模式

当 GPT 不可用时，系统必须降级为规则生成。

无 GPT 模式负责：

- 从结构化 JSON / Markdown 字段中抽取已有内容。
- 按页面类型套用固定页面合同。
- 按容量规则拆页。
- 按设计 token 和组件库渲染。
- 按配图策略选择已有图片、使用预设图像槽位、或降级为纯信息图。
- 用验收器检查信息完整度和可读性。

无 GPT 模式不保证产生新的深刻洞见。  
它保证的是：已有内容被稳定地组织成高质量阅读型 PPT。

### 3. 替代模型模式

如果未来没有 GPT，但有本地模型或其他 API，可以接入为“建议者”。

替代模型只输出建议：

- 页面类型建议
- 标题建议
- 摘要建议
- 视觉方向建议

最终仍由规则系统决定：

- 页面合同
- 容量拆页
- 布局选择
- 渲染
- 验收

## 核心设计原则

### 信息密度优先

每页必须包含足够信息，不能只是概念图。

默认阅读型页面至少包含：

- 页面标题
- 一句话结论
- 结构化内容区
- 关系或证据区
- 底部 takeaway / 最终洞见

特殊页面例外：

- 封面页
- 章节幕
- 转场页

这些页面可以低信息密度，但不能超过全 deck 的 15%。

### 中文可读性优先

所有默认输出使用中文。

规则：

- 不输出英文标签，除非原始内容是专有名词。
- 图中标签必须清晰可读。
- 字号不能低到只能装饰。
- 不生成假小字、乱码、装饰性文字。
- 每页最大正文块不超过 4 个。
- 每个文字块都要有明确功能。

### 页面是报告，不是海报

每页要回答一个问题：

- 这页在解释什么？
- 谁的观点在这里？
- 支撑证据是什么？
- 冲突在哪里？
- 读者最后应该带走什么？

如果一页不能回答这些问题，它不应进入阅读型主链路。

## 页面族

V13 不使用单一模板，而是使用页面族。

### 1. 封面 / 章节页

用途：建立主题和气质。

信息密度：低到中。

必须包含：

- 主题标题
- 副标题
- 书名 / 话题来源
- 专家数量 / 轮次 / 洞见数量

可选：

- 主题意象图
- 抽象背景图
- 大型关系图的一部分

### 2. 核心洞见页

用途：让读者快速看到最重要结论。

信息密度：中高。

页面合同：

- 标题
- 一句话总判断
- 3 到 5 条核心洞见
- 每条洞见 1 个短标题 + 1 到 2 行解释
- 底部“读者带走什么”

适合布局：

- 纵向洞见列表
- 双栏洞见卡
- 洞见金字塔
- 结论瀑布图

### 3. 圆桌讨论页

用途：呈现多位专家围绕同一议题的立场差异。

信息密度：高。

页面合同：

- 核心问题
- 一句话当前争议
- 6 位专家立场
- 立场轴线或二维矩阵
- 本页综合判断

适合布局：

- 立场光谱图
- 二维争议矩阵
- 专家观点列阵
- 中心议题 + 周边专家节点

### 4. 张力 / 冲突页

用途：解释观点之间的真正冲突。

信息密度：高。

页面合同：

- 冲突标题
- 冲突双方
- 攻击观点
- 回应观点
- 冲突本质
- 暂时结论

适合布局：

- 对抗双栏
- 法庭辩论式结构
- 冲突路径图
- 因果链路图

### 5. 结构解释页

用途：把复杂概念拆成可读结构。

信息密度：中高。

页面合同：

- 被解释概念
- 3 到 4 个组成层级
- 每层一句解释
- 层级之间的关系
- 底部概括公式或判断

适合布局：

- 三层架构图
- 议题树
- 漏斗图
- 因果链
- 系统地图

### 6. 总结页

用途：收束 deck。

信息密度：中。

页面合同：

- 最终判断
- 3 条可带走结论
- 1 条开放问题
- 1 条行动或反思建议

## 阅读型布局库

V13 第一批沉淀 8 个布局。

### `reading_brief_4zone`

四区阅读页。

区域：

- 问题定义
- 争议地图
- 专家观点摘录
- 读者带走什么

适用：

- 核心问题页
- 章节总结页
- 研究简报页

### `stance_spectrum`

立场光谱页。

区域：

- 左侧命题拆解
- 右侧专家立场地图
- 底部综合公式

适用：

- 圆桌讨论页
- 专家观点对比页

### `argument_matrix`

二维争议矩阵。

轴线示例：

- 个体选择 / 结构约束
- 文化解释 / 制度解释

适用：

- 张力分析
- 观点分布
- 争议地图

### `hub_and_spokes_dense`

中心议题 + 周边专家节点。

区域：

- 中心主题
- 6 个专家观点节点
- 关系线
- 底部综合洞见

适用：

- 圆桌总览
- 专家阵容带观点

### `clash_courtroom`

法庭式冲突页。

区域：

- 左侧攻击方
- 右侧回应方
- 中间冲突本质
- 底部判读

适用：

- clash
- counter-argument

### `insight_pyramid`

洞见金字塔。

区域：

- 顶部最终判断
- 中部三个支撑洞见
- 底部证据或案例

适用：

- 核心洞见页
- 最终总结页

### `causal_chain`

因果链路页。

区域：

- 起点
- 中间机制
- 放大器
- 结果
- 反直觉结论

适用：

- 代价分析
- 人性分析
- 机制解释

### `quote_evidence_grid`

观点 + 证据网格。

区域：

- 专家观点
- 原文 / 案例证据
- 解释
- 洞见

适用：

- 书籍洞见
- 证据页

## 设计 token

V13 设计沉淀为 token，而不是靠每次 prompt 临场发挥。

### 字体

默认：

- 标题：中文黑体 / 思源黑体 / 微软雅黑，粗体
- 正文：中文无衬线，14 到 18px
- 标签：等宽或窄体，但必须中文可读

可选：

- 出版风格可使用宋体 / 思源宋体作为标题。
- 咨询风格不使用装饰字体。

### 字号层级

阅读型 16:9 默认：

- 主标题：34 到 48px
- 副标题 / 一句话判断：20 到 26px
- 区块标题：18 到 22px
- 正文：14 到 17px
- 标签：12 到 14px

低于 12px 的文字默认禁止，除非是页码、装饰编号、非必要元信息。

### 配色

默认主题：

- 背景：象牙白 / 暖白 / 深炭黑
- 正文：深灰 / 黑色 / 暖白
- 强调：哑金
- 冲突：克制红
- 结构线：蓝灰 / 中性灰
- 补充：低饱和玉色

禁止：

- 大面积高饱和渐变
- 全页单色紫蓝
- 随机彩虹色
- 文字与背景对比不足

### 间距

原则：

- 页面四周留白 48 到 80px。
- 区块之间通过间距和分割线区分，少用重阴影。
- 同类内容对齐。
- 不做卡片套卡片。

## 生图与配图逻辑

V13 必须把图像策略沉淀下来。

### 图像类型

允许的图像类型：

- 主题意象图
- 关系图背景
- 专家肖像
- 书籍封面
- 场景隐喻图
- 信息图辅助图标
- 纹理背景

不鼓励：

- 纯装饰图
- 和内容无关的 stock 图
- 难以识别主体的暗图
- 抢正文注意力的大图

### 使用优先级

1. 用户提供的真实素材。
2. 项目中已有素材。
3. 可合法访问的公开图片。
4. AI 生成主题图。
5. 纯信息图布局，无配图。

### 什么时候必须生图

以下页面可以生图：

- 封面
- 章节页
- 高概念总结页
- 需要主题意象的书籍页

以下页面默认不生图：

- 圆桌讨论页
- 高密度专家立场页
- 张力矩阵页
- 证据页

这些页面以信息图、文字结构和关系图为主。

### 生图 prompt 合同

所有生图 prompt 必须包含：

- 主题
- 读者用途：阅读型 PPT，不是演讲背景
- 输出比例：16:9
- 中文-only 要求
- 页面信息密度要求
- 核心主体
- 必须出现的中文标签
- 禁止假小字、乱码、裁切
- 风格方向
- 配色方向

示例：

```text
生成一张 16:9 阅读型 PPT 单页，不是演讲背景。
主题：文化属性真的决定命运吗。
所有可见文字只使用中文。
页面必须能独立阅读，包含标题、核心判断、专家立场、关系图、最终洞见。
核心主体是“文化属性”。
必须出现标签：强势文化、弱势文化、遵循规律、破格获取、丁元英、马克思、芒格。
文字必须清晰可读，不要假小字，不要乱码，不要裁切。
风格：高级研究简报，暖白纸面，深灰文字，哑金强调，克制红表示冲突。
```

### 无 GPT 时的配图降级

没有 GPT 时，系统不尝试生成复杂图片 prompt。

降级路径：

1. 如果有书封或真实素材，使用真实素材。
2. 如果没有素材，使用纯信息图组件。
3. 如果页面需要意象，用预设主题图 prompt 模板填字段。
4. 如果字段不足，不生图。

原则：宁可没有图，也不要放错图。

## 页面合同

每个页面类型必须有数据合同。合同缺字段时，系统按规则降级。

### 圆桌讨论页合同

必需字段：

- `title`
- `core_question`
- `stances`
- `synthesis`

`stances` 每条包含：

- `expert`
- `stance`
- `position_label`

无 GPT 生成 `position_label` 时使用规则：

- 包含“文化”且支持丁元英观点：文化解释
- 包含“制度”“法律”“法”：制度解释
- 包含“资本”“生产关系”：资本解释
- 包含“道”“自然”“无为”：规律解释
- 其他：综合解释

### 冲突页合同

必需字段：

- `title`
- `attacker`
- `target`
- `attack`
- `defense`
- `conflict_essence`
- `takeaway`

无 GPT 缺 `conflict_essence` 时：

- 从 `attack_type` 取值。
- 如果仍缺，使用“观点冲突”。

### 洞见页合同

必需字段：

- `title`
- `thesis`
- `insights`
- `takeaway`

`insights` 每条包含：

- `title`
- `explanation`
- `evidence`

缺证据时，标记为“待补证据”，但不阻塞渲染。

## 无 GPT 质量保障

V13 的保底质量来自四件事：

1. 页面合同。
2. 布局白名单。
3. 设计 token。
4. 验收器。

### 信息量验收

每页必须达到最低信息量。

规则：

- 普通阅读页至少 5 个信息块。
- 圆桌页至少 4 位专家观点，推荐 6 位。
- 冲突页必须有攻击和回应。
- 洞见页至少 3 条洞见。
- 总结页至少 3 条 takeaway。

低于标准时：

- 如果源内容足够，自动拆补。
- 如果源内容不足，生成 `quality_warning`。
- 发布模式下 warning 需要展示在运行日志中。

### 可读性验收

必须检查：

- 字号不低于最小值。
- 文字块没有溢出。
- 页面没有内部滚动。
- 文本与背景对比足够。
- 每页标题存在。
- 每页 takeaway 存在，封面页除外。

### 设计一致性验收

必须检查：

- 同一 deck 不超过 2 个主色系统。
- 同一页面不超过 3 个强调色。
- 不出现随机 inline style。
- 页面类型使用允许的布局。
- 不出现装饰性假文字。

## V13 与 V12 的关系

V12 是稳定渲染底座。

V13 在 V12 前面新增：

```text
Content JSON / Markdown
  ↓
V13 Design Director
  ↓
Page Contracts
  ↓
Reading Layout Planner
  ↓
V12 Renderer / V13 Renderer Extension
  ↓
V13 Quality Validator
```

V13 不废弃 V12。

V13 改造重点：

- 扩展 `Page` 数据结构。
- 增加 `design_brief`。
- 增加 `takeaway`。
- 增加 `blocks`。
- 增加布局族。
- 增加质量验收。

## 实施边界

第一阶段实现：

- 页面合同。
- 3 个阅读型布局：`reading_brief_4zone`、`stance_spectrum`、`clash_courtroom`。
- 无 GPT 稳定模式。
- 设计 token。
- 信息量验收。
- 可读性验收。
- V13 规格写入 `SKILL.md`。

第二阶段实现：

- GPT 增强模式。
- 生图 prompt 自动生成。
- 真实素材接入。
- 更多布局族。
- 浏览器视觉 QA 自动化。

第三阶段实现：

- 多主题系统。
- 主题自动选择。
- 专家肖像 / 书封 / 主题意象生成。
- 设计评分自进化。

## 成功标准

V13 第一阶段完成后：

- 没有 GPT 也能生成阅读型 PPT。
- 圆桌页不再只是两张发言卡，而是有立场地图和综合判断。
- 冲突页不再只是攻击/回应两栏，而是有冲突本质和结论。
- 洞见页不再只是卡片堆叠，而是有清晰 thesis、证据、takeaway。
- 每页信息密度达到阅读型标准。
- 视觉风格通过 token 固化。
- 配图逻辑明确：该用图时用图，不该用图时不硬塞图。
- 验收器能发现信息量不足和缺少 takeaway 的页面。

## 非目标

V13 第一阶段不做：

- 完整 AI 生图流水线。
- 自动联网找图。
- PPTX 导出。
- 重写 V11 训练系统。
- 删除旧模板。
- 追求所有页面像海报一样漂亮。

V13 的第一优先级是：**可读、稳定、高信息密度、有设计下限**。
